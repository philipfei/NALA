# NALA_v1 变更说明（相对 NALA_v0）

2026-10-07 · v1.0.0 · v0 的完整说明见 `CHANGES_v0.md`，文件里没提到的源文件与 v0 完全相同。

## 一览
| # | 改动 | 位置 |
|---|---|---|
| 1 | **M2、M3 电机方向极性反相**（M1、M4 不变） | `config.h` `MOTORn_DIR_INVERT`，`motor_functions.c` |
| 2 | **20 Hz**：控制周期 100 → 50 ms；回传保持 **10 Hz**；超时 500 → **200 ms** | `config.h` |
| 3 | **速度控制器重写**：旧 PID → 位置式 PI + 前馈 + 抗饱和，修复长时间振铃 | `main.c` `speed_control()`，`config.h` `PI_*` |
| 4 | PWM 输出分辨率 1 % → 1/255 | `motor_functions.c` |

## 1. M2、M3 极性反相
- `config.h` 新增 `MOTOR1..4_DIR_INVERT`：M2、M3 = 1，M1、M4 = 0。1 表示该电机的方向引脚电平取反，使"正功率 = 该轮向前"。
- 模型测试：M1、M4 的方向与 v0 完全一致，M2、M3 对所有非零功率恰好相反（`tests/motor_polarity_model_test.py`）。
- 编码器符号 `MOTORn_ENC_SIGN` **没有改**。某个轮子上车后方向不对，把对应的标志改回即可。
- 附带一个推测（我无法从数据确认）：如果 v0 里这两个轮子的电机极性真是反的，速度环对它们就是正反馈，会加重"反复摆动"。极性改对后，下面的控制器才有意义。

## 2. 20 Hz、回传 10 Hz、超时 200 ms
- **控制周期 50 ms**（Timer3 `OCR3A = 12499`，已在反汇编里核对）：测速、控制、命令都按 20 Hz。一个编码器计数 = 0.082 rad/s。
- **回传保持 10 Hz**（`TELEMETRY_EVERY_N_TICKS = 2`），格式与原版完全一致（6 位小数）。为什么不会堆积（`tests/tx_budget.py`）：

  | 回传频率 | 一行 | 线路占用（9600 波特率） | 20 秒仿真 |
  |---|---|---|---|
  | 20 Hz | 最长 50 字节 ≈ 52 ms | **104 %，发不完** | 丢 15 行，缓冲顶满 128/128 |
  | **10 Hz** | 同上 | **52 %** | 丢 0 行，缓冲峰值 50/128 |

  回显开关打开时（20 Hz 指令 → 约 62 % 额外负载），总量会超过线路容量，部分回显/回传行会被丢弃（不阻塞）。**回显只用于调试**。
- **超时 200 ms**：运动中 200 ms 没收到速度帧就停车并发 `cmd timeout`，实际停车在最后一帧之后 **200–250 ms**（`tests/timeout_model_test.py` 10/10 通过：所有相位都在窗口内；20 Hz 与 150 ms 间隔不会误停，300 ms 间隔会停）。
- **对 Pi 的要求**：速度帧以 **20 Hz** 持续发送（最慢每 150 ms 一次）。本机 2022 年的 `motor_uart_comms.py` 速度不变时不发送，而上游只有 3–10 Hz，所以必须加一个 20 Hz 定时重发，并保证停车条件同时把"当前指令"置零。细节与 20 Hz 可行性核对见 `docs/protocol.md` §7、§8。

## 3. PID 修复
**现象**：电机为了恢复稳定反复摆动，停下之前长时间振动。

**v0 控制器最可能的原因**（四点都能在代码里指出来；仿真复现了现象，但我没有在真实机器人上测过，所以是推断）
1. **双重积分**：`pwm -= (Kp·e + Ki·∫e + Kd·de/dt)`。u 里已经有积分项，又被每个周期累加进 pwm，相当于积分的积分，天然带 180° 相位滞后，会持续振铃。
2. **`u` 被截断成 `int`**：小于 1 的修正量被丢掉，形成死区和极限环。
3. **输出是整数百分比**：1 % 一档 ≈ 0.25 rad/s，积分控制会在相邻两档之间来回跳。
4. **停车后积分残留**：`old_int_error` 在停车指令后还留着，而 pwm 被复位为 0，于是围绕零速振荡很久。
把周期缩到 50 ms 会让它更糟（每秒的修正次数翻倍）。

**v1 的控制器**（`speed_control()`）
```
e   = 目标 − 测量                         （教科书符号）
pwm = PWM_PER_RAD_S·目标 + PI_KP·e + I
I  += PI_KI·e·dt   （限幅 ±25 %；输出饱和时不再积分）
目标 = 0  →  pwm = 0，I 清零
目标变号  →  I 清零
```
`PI_KP = 1.0`，`PI_KI = 8`，不带微分（速度估计有 0.082 rad/s 的量化，微分只会放大噪声）。

**仿真依据**（`tests/pid_sim.py`；电机模型是**假设的、没有实测**：增益 G ∈ {0.15, 0.25, 0.40} rad/s 每 %，时间常数 τ ∈ {0.05…0.4} s，静摩擦死区 0 或 6 %，共 24 种工况；含编码器量化）

| | v0 控制律（100 ms） | v0 控制律（50 ms） | **v1 控制器（50 ms）** |
|---|---|---|---|
| 停车后反向转动次数（最多） | 3（24 种工况里 22 种出现） | 4 | **0** |
| 稳态波动（最大） | 10.3 rad/s | 12.1 rad/s | **0.17 rad/s** |
| 停车时间 | 多数工况到 2.5 s（仿真窗口上限）仍未静止 | 同左 | **等于电机自然滑行时间** |
| 降速 3→1.5 / 反向 3→−3 的稳态波动（最大） | 18.5 / 30.9 rad/s | 未测 | **0.14 / 0.40 rad/s** |

- v1 剩余的过冲只在电机增益比前馈假设高 60 % 时出现（前馈推过头），不是回路振荡；G ≤ 0.25 时过冲约 25 % 以内。
- **局限**：这是对"假设电机"的仿真，不能保证真实机器人上一定没有振动。真实电机的 τ、增益、静摩擦、齿轮间隙都没测过。Kp = 1、Ki = 8 是我综合过冲、调节时间和波动在扫描结果里选的折中，不是严格最优。

**上车后的调整方向**（定性经验，来自仿真趋势）
| 现象 | 调整 |
|---|---|
| 起步冲过目标再回落 | 降低 `PWM_PER_RAD_S`（如 3.5） |
| 到不了目标 / 很慢才到 | 提高 `PWM_PER_RAD_S`，或提高 `PI_KI` |
| 稳态仍小幅抖动 | 降低 `PI_KI` |
| 响应迟钝 | 提高 `PI_KP`（1.5–2） |
改参数后建议用 `pid_sim.py` 先跑一遍。

**行为变化**：停车（目标 0）时现在是**断开输出让电机自然滑行**，不再用 PID 主动反向制动；滑行距离取决于机械摩擦。

## 4. PWM 分辨率
`set_motor_power()` 改为 `float` 百分比，按 8 位 PWM 的 1/255 输出（v0：整数百分比，101 档；v1：256 档）。整数输入时与 v0 的比较值最多差 1 个计数（舍入 vs 截断）。

## 对 Pi 开发的影响（PID → PI）
- **接口无影响**：控制器参数都在 MCU 内部，帧格式、回传格式、串口参数不变，Pi 也不读取 MCU 的回传。
- **行为变化**：停车（目标 0）改为断开输出自然滑行，不再主动反向制动，停车距离可能略长（取决于机械摩擦，未实测）；依赖"快速停住"的 Pi 逻辑（如 `hardcoded_cleaning.py` 的小幅移动、`wheel_contamination` 停车）需留意。速度响应更平稳，对导航只有好处。
- **真正需要 Pi 改的**与 PI 无关：缩放 /50、超时 200 ms、20 Hz 持续重发。

## 验证情况
- Studio 工具链命令行编译，Debug / Release 均 `-Wall -Wextra` **0 警告**。**Studio 本体构建 Release 成功**，产物与命令行构建哈希一致：Flash 9358 B（28.6 %）、RAM 340 B（16.6 %）（v0：约 8.5 KB，浮点运算增加）。
- `NALA_v1` 需要 `motor_driver_C.componentinfo.xml`（Studio 自动生成的组件缓存）才能被 Studio 命令行构建，已补入。它与 v0 工程的 GUID 相同，在 Studio 里请先关闭 v0 再打开 v1。
- 模型测试全部通过：极性、超时（10/10）、PID 仿真、串口预算。**均为模型/仿真，不是固件实测。**
- **尚未在真实硬件上验证，也尚未烧录。**

## 上车验证（车轮悬空）
1. 上电：串口应先出现 `a`、`test`，之后**每 100 ms** 一行四个轮速（6 位小数）。
2. 发 `80 86 05 00 00`（+Vx = 0.10 m/s，**20 Hz 持续发**）：四个轮子都应**向前**转，转速接近 2.5 rad/s，回传里四列都是正值。**重点看 M2、M3 方向对不对**。
3. 阶跃：先停、再发上面的指令，看速度是否平稳上到目标，有无反复摆动。
4. 停车：发 `80 86 00 00 00`，轮子应顺势停下，**不应再反向抖动**。
5. 超时：发一条后不再发送，约 0.2–0.25 s 后应停车，串口收到 `cmd timeout`。
6. 再用 `80 86 00 05 00`（+Vy 向左平移）和 `80 86 00 00 19`（逆时针）核对方向。
