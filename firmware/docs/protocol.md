# NALA_v1 电机驱动：通信协议与接口

版本 v1.0.0 · 2026-10-07 · 固件 `NALA_v1/motor_driver_C` · 状态机图见 [`state_machine.svg`](state_machine.svg)

## 1. 链路
UART0，**9600 8N1**，无流控。MCU：ATmega328PB，RXD0 = PD0，TXD0 = PD1（TTL 电平）。

## 2. 上位机 → MCU

| 帧 | 字节 | 作用 |
|---|---|---|
| 速度帧 | `80 86 Vx Vy w` | 设定车体速度 |
| 回显开关帧 | `80 87 E` | `E=01` 开 / `E=00` 关命令回显，其他值忽略 |

- `Vx Vy w` 为 **int8**（补码）：`Vx/50` → m/s，`Vy/50` → m/s，`w/50` → rad/s。**每个计数 0.02**，范围 −2.56 … +2.54。上位机发送时用 `值 × 50`。
- 方向约定：**ROS 标准（REP-103）**，未在机器人上验证：
  - **Vx = 向前**（ROS `linear.x`）；
  - **Vy = 向左**（ROS `linear.y`）；
  - **w** = 逆时针为正（ROS `angular.z`）。
- 帧格式沿用原版；**缩放由原来的 /100（0.01）改成 /50（0.02）**。回显开关帧、超时停车是 NALA_v0 起新增的。上位机的要求见 §7。

示例（0.02 每计数；负数用补码，如 −5 = `FB`）：

| 动作 | 字节 |
|---|---|
| 停车 | `80 86 00 00 00` |
| 前进 0.10 m/s（Vx = 5） | `80 86 05 00 00` |
| 倒退 0.10 m/s（Vx = −5） | `80 86 FB 00 00` |
| 向左平移 0.10 m/s（Vy = 5） | `80 86 00 05 00` |
| 逆时针 0.50 rad/s（w = 25） | `80 86 00 00 19` |
| 回显开 / 关 | `80 87 01` / `80 87 00` |

**行为说明**
- **超时自动停车**：小车在运动时，如果 **200 ms**（`CMD_TIMEOUT_MS`，v0 是 500 ms，设为 0 可关闭）内没有收到速度帧，就把所有目标置零停车，并发一次 `cmd timeout`；收到新的速度帧立刻恢复。因此**行驶中上位机必须持续重发指令**，建议 **20 Hz（每 50 ms 一次）**，最慢不要超过每 150 ms 一次。
  - 检查每 50 ms 做一次，实际停车发生在最后一帧之后 200–250 ms。
  - 零速度帧（停车）本身不会超时。
  - 回显开关帧不会刷新超时，只有速度帧才算"上位机还活着"。
- 收到速度帧立即输出前馈 PWM，之后每 50 ms（20 Hz）由 PI 控制器按编码器反馈修正。
- 新帧覆盖尚未处理的旧帧；指令频率没有限制。
- 解析靠帧头 `80 86` / `80 87` 同步，载荷字节不再检查帧头；丢字节后会错位，直到下一个帧头重新同步。

## 3. MCU → 上位机（文本行，以 `\n` 结尾）

| 内容 | 格式 | 何时发送 |
|---|---|---|
| **轮速回传** | `%f \t %f \t %f \t %f\n`，如 `0.000000 \t 2.451000 \t …` | **每 100 ms 一行（10 Hz）** |
| 启动信息 | `a\n`、`test\n` | 复位后各一次 |
| 命令回显 | `Vx Vy w\n`，如 `0.100000 0.000000 0.000000`（m/s, m/s, rad/s） | 每收到一条速度帧，**仅回显开启时**（默认关） |
| 回显确认 | `echo on\n` / `echo off\n` | 收到有效的回显开关帧后 |
| 超时通知 | `cmd timeout\n` | 小车在运动、超时未收到速度帧而停车时，发一次 |

- 轮速回传依次为 **M1 M2 M3 M4** 的实测角速度，单位 **rad/s**；**正值 = 该轮推动车体向前**（编码器符号已按左右镜像安装修正）。
- 发送走 128 字节环形缓冲。缓冲放不下时，这一行直接丢弃，不会阻塞控制。解析时请按行读取，并忽略不是 4 个数的行。

## 4. 硬件接口

| 电机 | PWM 引脚 | 方向引脚 | 编码器 A / B | 编码器符号 | 运动学符号 Vx / Vy / w |
|---|---|---|---|---|---|
| M1 | PD6 (OC0A) | PE0 | E1: PB3 / PB4 | −1 | + / − / − |
| M2 | PD5 (OC0B) | PE1 | E2: PD2 / PD3 | −1 | + / + / − |
| M3 | PB1 (OC1A) | PE2 | E3: PD4 / PD7 | +1 | + / − / + |
| M4 | PB2 (OC1B) | PE3 | E4: PC2 / PC3 | +1 | + / + / + |

**电机方向极性（v1）**：M2、M3 的方向引脚相对 v0 反相（`config.h` 的 `MOTORn_DIR_INVERT`，M1、M4 不变），使「正功率 = 该轮向前」与编码器的正速度同向。某个轮子方向不对时，改对应的标志即可。

轮子位置按 ROS 约定（x 前、y 左）**假设**为：M1 左前、M2 左后、M3 右后、M4 右前（上表的运动学符号与这个假设一致）。**尚未在机器人上验证**，上车时用悬空的纯 Vx / 纯 Vy / 纯 w 指令核对。

```
        前 (+Vx)
 M1 (FL)    M4 (FR)         左 = +Vy
 M2 (RL)    M3 (RR)         逆时针 = +w
        后
```

- 电机与编码器的对应关系（`MOTORn_ENCODER`）、符号（`MOTORn_ENC_SIGN`）、各编码器引脚，都在 `config.h` 末尾的 "WIRING MAP"。编号越界或同一编码器被重复分配时，编译会报错。
- PWM 引脚固定在定时器输出上（Timer0 / Timer1），不能随意改。

## 5. 关键参数（`config.h`）

| 参数 | 值 |
|---|---|
| 轮半径 / 半轮距 / 半轴距 | 0.040 / 0.160 / 0.130 m |
| 控制周期（Timer3，精确） | **50 ms（20 Hz）**；回传每 2 个周期一行（10 Hz） |
| 编码器每转计数 | 1536（沿用原值，未在本硬件上重新核对） |
| 速度控制器 | 位置式 PI + 前馈 + 抗饱和：Kp 1.0 · Ki 8 · 积分限幅 25 %（v0 的 PID 已替换，见笔记） |
| 前馈 / 限幅 | 4.0 PWM/(rad/s) · ±100 |

## 6. 快速测试（Python + pyserial）
```python
import serial
s = serial.Serial("COM5", 9600, timeout=1)
import time
s.write(bytes([0x80, 0x87, 1]))                     # 打开回显
for _ in range(10):                                 # 行驶中要持续重发 (超时 200 ms)
    s.write(bytes([0x80, 0x86, 5, 0, 0]))           # 前进 0.10 m/s (Vx = 0.10 / 0.02 = 5)
    time.sleep(0.05)                                # 20 Hz
    print(s.readline())                             # 轮速行 / 回显行
s.write(bytes([0x80, 0x86, 0, 0, 0]))               # 停车
# 负数: bytes([0x80, 0x86, (-5) & 0xFF, 0, 0])
```

## 7. 对上位机（Pi）的要求
1. **缩放与轴向**：`Vx = linear.x × 50`，`Vy = linear.y × 50`，`w = angular.z × 50`（取整，限制在 ±127 内）。缩放不对，速度会差 2 倍；Vy 符号不对，横移方向会反。
2. **持续重发（必须）**：行驶中以 20 Hz（每 50 ms）重发速度帧，最慢不超过每 150 ms 一次（MCU 超时是 200 ms）。
   - 现有 `catkin_ws/.../motor_uart_comms.py`（2022 年原版，**未被修改**）只在速度变化时才发送（第 52–53 行 `isclose` 去重）。
   - 上游频率也不够：手柄补发 5 Hz（`motor_comms.launch`）、手柄节点 10 Hz（`joy_processor.py`）、导航控制器 3 Hz（`move_base.launch`）。所以不能只靠转发收到的 `cmd_vel`，需要一个 20 Hz 定时器。
3. **推荐实现**
   - 维护一个共享的"当前指令"：收到新的 `cmd_vel` 时更新并**立即发送**，定时器每 50 ms 重发当前指令。
   - 所有停车条件（`wheel_contamination`、污染处理、节点退出）必须同时把"当前指令"置零，否则定时器会用旧的非零指令覆盖停车（注意 `wheel_contamination_cb` 里有 `sleep(1)`）。
   - 5 个字节用一次 `ser.write` 发出（现在是 5 次单字节写）。
4. **接收缓冲**：Pi 不读 MCU 回传时，内核串口接收缓冲会一直累积（满了丢弃，不影响运行）；读回传前先 `ser.reset_input_buffer()`。

## 8. 20 Hz 可行性（理论核对；负载为估算，未实测）

| 环节 | 结论 | 依据 |
|---|---|---|
| 串口线路（Pi→MCU） | 可行 | 5 字节/帧 = 5.2 ms；20 Hz 只占该方向的 10.4 %；线路上限约 190 帧/秒；全双工，回传在另一根线上 |
| 回传（MCU→Pi） | **10 Hz 可行，20 Hz 不行** | 一行最长 50 字节 ≈ 52 ms（9600）；10 Hz 占 52 %，20 Hz 占 104 % |
| MCU | 可行 | 每条命令约 0.3 ms，控制步约 1–3 ms，加编码器中断，估计总负载 < 15 % |
| Pi 硬件 / 串口 | 可行 | 吞吐远低于 mini-UART 能力；波特率漂移是精度问题，与速率无关 |
| Pi 软件 | **需要改** | 上游只有 3–10 Hz，必须加定时重发（见 §7） |
